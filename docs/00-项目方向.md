## 一、一句话定位

> 面向企业财务、代理记账机构与财税职业院校的**可解释税务风险识别引擎**——同一审计内核，支撑企业检查与仿真实训。

**企业端业务核心（已确认）**：依据用户上传的材料，排查偷漏税风险线索、账税差异与财务数据异常，并揭示资料缺失导致的检查盲区。最终审计报告必须说明发现的问题、来源和计算依据、建议核查事项、已完成的检查及仍无法判断的事项。发现差异不等于认定偷漏税，检测完成不等于风险已经整改；缺资料不能算通过，也不能由 LLM 补造事实。这里的范围是税务与财务风险排查，不是泛化的融资、投资或市场风险评估。

**不做的事**（边界，越清楚越有说服力）：

- 企业自用与机构管理多客户两种使用场景都支持；是否开展企业直销、收费及获客不由这次功能确认决定，旧直销限制不再作为企业使用的功能禁令
- 不做面向税务机关的监管侧产品（与「服务小微企业」定位冲突，政务采购非学生团队可触达）
- 不自训模型、不承诺准确率数字、不对接真实税务系统

## 四、目标市场与产品形状

| 市场 | 角色 | 定位 |
| --- | --- | --- |
| 财税职业院校 | **主线** | 税务风险审计实训沙箱。出题 → 学生查账 → 自动评分 |
| 代理记账机构 | **出口** | 管理多家客户；每次检测一家企业、一个主期间，输出风险清单与证据报告 |
| 企业财务 | **企业自用场景，已确认支持** | 对本企业上传材料、确认范围、检查账税风险并留存报告；获客方式另定 |

**为什么院校是主线**：赛道为职教赛道，评审天然偏好「赋能职业教育」；且学校自身即有真实教学场景、教师与学生可试点。这是唯一能拿到真实用户反馈与真实数据的地方。

**为什么代账是出口**：机构本身即渠道——服务一家机构，即触达其背后数十家小微企业，无需自建获客。

**使用范围与商业渠道分开**：此前不做企业直销的理由属于获客与商业实施判断，不限制企业财务使用同一检测能力。使用平台的机构与被检测企业是两个层级；业务材料按机构权限隔离、按被检测企业归集，不因相同税号跨机构打通数据。

企业端已确认流程：直接上传 → 识别并核对企业/税号/主检测期间 → 提示必须处理、缺失但可继续、建议补充事项 → 用户确认材料快照 → 执行适用规则 → 展示结果、导出报告，并围绕结果核验和提问。原件和操作链路应可追溯；原件留存及细粒度日志仍需实现，不能沿用旧“不留原件”的交付结论。

## 五、技术路线：识别与解读分离

```
        ┌──────────────────────────────────────┐
        │   可解释的税务风险引擎（唯一内核）      │
        │  ┌────────────┐  ┌────────────┐      │
        │  │ 识别层      │  │ 解读层      │      │
        │  │ 确定性规则   │  │ LLM         │      │
        │  └────────────┘  └────────────┘      │
        └──────────────────────────────────────┘
                  ↓                  ↓
        ┌────────────┐      ┌────────────┐
        │ 院校实训沙箱 │      │ 代账作业台  │
        └────────────┘      └────────────┘
```

### 识别层 —— 确定性，可举证

**绝不用 LLM 做风险判断。** 审计场景容错率为零，LLM 幻觉无法举证。识别层全部走确定性逻辑：

- 税会差异比对
- 进销项勾稽（进项采购规模 vs 销项开票收入）
- 四流一致校验（合同流 / 发票流 / 资金流 / 货物流）
- 关联方识别与关联交易网络（图算法，非「知识图谱」）
- 行业指标偏离度（毛利率、税负率对标同地区同行业）

### 解读层 —— LLM 只做三件事

1. 把命中的规则翻译成业务人员能看懂的话
2. 生成合规审计报告
3. 问答式讲解（实训场景中充当「带教师傅」）

> 答辩话术由此从「我们准确率 99.5%」变为「我们内置 N 条可溯源风险规则，每条给出触发明细与法条依据，支持人工复核」。前者一碰即碎，后者越问越硬。

## 七、数据来源（学生项目最现实的问题）

1. **公开税务稽查案例、上市公司补税公告** —— 真实、可引用、有出处（如近 60 家上市公司补税超 35 亿元）
2. **会计准则 + 税法条款** —— 规则库的原始依据
3. **学校教师实务经验** —— 规则优先级的来源
4. **代账机构脱敏样例** —— 需签署授权，用于沙箱场景仿真

## 九、与现有原型的差距

现有 `prototype/税海拾珠-AI税务审计平台.html` 为界面原型，**仅可用于对齐产品形态，不可作为技术基线**。落地时需重构的部分：

| 项 | 原型现状 | 落地要求 |
| --- | --- | --- |
| 角色 | 5 个（含「税务机关」） | 砍「税务机关」；保留院校（教师/学生）+ 代账（机构/会计） |
| 数据 | `mockData` 内存态，刷新即丢 | 需持久化 |
| AI | 关键词匹配本地文本，无模型调用 | 需真实规则引擎 + LLM 解读层 |
| 评分 | `Math.random()` | 需可解释的评分标准 |
| 解析 | 上传控件仅读文件名与大小 | 需模板导入 + 字段映射 |
| 鉴权 | 密码硬编码 `123456`，角色由下拉框决定 | 需真实鉴权与权限隔离 |
| 安全 | 全量 `innerHTML` 拼接用户输入 | 需输入转义 |
