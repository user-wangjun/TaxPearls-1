# TaxPearls 部署、备份恢复与回滚

本文是 FR-G08 的运维基线及 FR-F10 的本机工程验收说明。备份允许在线执行；恢复和版本回滚必须安排维护窗口。以下容器命令是部署操作说明，不代表当前 Docker 镜像或生产环境已经验收。

登录限流同时按账号与客户端 IP 计数。反向代理部署时在 `.env` 的 `TAXPEARLS_TRUSTED_PROXY_IPS` 填写**代理连接应用时的固定源 IP**，并确保代理传递真实客户端 `X-Forwarded-For`；不要填写 `*` 或信任不受控来源。未正确配置时，应用会把代理视为同一个客户端 IP，导致其后的用户共享限流额度。服务保持单进程单副本；扩为多副本前须把限流状态迁至共享存储。

## 1. 数据库备份与校验

邀请链接部署边界：生产须使用 HTTPS；`/p/<code>` 含持有者凭证，不应原样写入代理/CDN/APM 访问日志或错误追踪，须按该路由关闭记录或把凭证段脱敏（邮箱/重置查询参数也须脱敏）。应用的邀请落地页发送 `no-store`、`no-referrer` 与 `noindex`，前端读取后清除地址栏凭证；这些措施不能替代外部代理日志配置，也不能撤回收件人保存的副本。本机使用模拟邮件验证注册链路，生产邮件送达、HTTPS 与外部日志配置尚未验收。

G11 邮箱认证部署与迁移：

- 生产配置 `TAXPEARLS_PUBLIC_BASE_URL=https://你的站点域名`（仅源站，不带路径、查询、片段或用户信息），同时设 `TAXPEARLS_COOKIE_SECURE=1`。缺失可信基址时，非回环请求的邮件申请返回 503；不要依赖客户端 Host 或不可信转发头拼接邮件链接。本机 HTTP 仅允许 localhost、127.0.0.1、::1。
- 注册/邮箱登录发送六位验证码与独立长令牌链接 `/#email=...`，密码重置发送长令牌链接。URL 片段不进入 HTTP 请求，页面读取后清除地址栏；显式确认才兑换，不能把 GET 预取当作本人同意。代理/APM 不得记录请求体里的令牌、验证码、Cookie、密码，也不得保存含敏感 URL 的前端遥测。
- `taxpearls_email_browser` 为 HttpOnly、SameSite=Strict 发起 Cookie。须在发起请求的同一浏览器、同一站点打开链接（可新标签页）；默认浏览器或邮件内置浏览器不一致时，请复制到原浏览器，或在新浏览器重新申请。退出登录会删除发起 Cookie；清除 Cookie 后不能继续原流程。
- 两通道共用原始 10 分钟期限，五次错误或重新发送使旧凭证失效。注册/重置确认后的短期证明仅留在当前页内存，刷新或关闭后须重新申请。成功重置会撤销该账号全部会话和待用邮箱凭证，停用成员也撤销凭证，恢复不复活。
- 启动迁移只新增凭证字段及索引，不把旧无绑定邮件升级成可信证明；切换后的公开入口拒绝旧凭证，用户需重新申请。备份中只有凭证摘要，但包含会话/用户等敏感信息，仍按本章加密管理；恢复后未过期凭证仍需原发起 Cookie，恢复/回滚前应评估旧会话与撤销状态复活风险。
- 本机验收使用模拟邮件传输；生产域名 SPF/DKIM、真实送达、HTTPS、Secure Cookie 与代理日志配置需独立验收，不以本机测试替代。

容器内数据库固定为 `/data/taxpearls.db`，命名卷为 `taxpearls-data`。备份使用 SQLite Online Backup API，不直接复制可能仍在 WAL 模式写入的数据库文件。

```bash
# 先由受控配置向容器注入独立 TAXPEARLS_BACKUP_KEY；不要在命令行填写密钥。
# --output 目录必须已经存在；也可指定尚不存在的完整文件名。
# 30 天仅为示例，操作者须按实际政策明确选择保留期。
docker compose exec -T taxpearls python scripts/ops_db.py backup-encrypted \
  --database /data/taxpearls.db --output /data/backups/manual.tpbackup --retention-days 30

# 将备份复制到宿主机或异地存储后再次校验
python scripts/ops_db.py verify-encrypted backups/manual.tpbackup
```

加密文件包含认证头、创建/到期时间及密文，不依赖可替换的独立清单。校验输出密文 SHA-256、文件大小、SQLite `quick_check`、schema version 和每张业务表的记录数；错误密钥、篡改、截断或数据库损坏均禁止恢复。校验输出含业务表统计，仍须按受控运维记录保管。

### 1.1 密钥、存储与兼容边界

专用 `TAXPEARLS_BACKUP_KEY` 须由操作者安全设置到进程环境，值为独立 32 字节随机密钥的 Base64；本脚本不自动读取 `.env`，不从命令行接收密钥，不复用邮件/模型密钥。Compose 的 `env_file` 可注入受控配置，但配置本身须限制访问。密钥与备份分开保管，丢失密钥无法解密；不自动创建生产密钥或安排定时任务。轮换时保留仍有有效备份/回执对应的旧密钥，按 `key_id` 人工选择正确密钥再校验，不静默降级或提前注销旧密钥。

```powershell
# 先从受控秘密存储注入 TAXPEARLS_BACKUP_KEY，再执行；不要把明文密钥写进命令历史。
.\.venv\Scripts\python.exe scripts\ops_db.py backup-encrypted --database instance\taxpearls.db --output backups\manual.tpbackup --retention-days 30
.\.venv\Scripts\python.exe scripts\ops_db.py verify-encrypted backups\manual.tpbackup
```

上例 30 天仅是操作示例，不是默认或法定保留期。保留期参数必须显式提供，允许 1–3650 天，范围不是合规认定。创建前禁止覆盖既有文件；一致性快照及认证后 SQLite 校验在内存进行，不另落明文备份，文件上限约 512 MiB，实际需为多份内存副本预留容量，不代表大库性能验收。备份发布使用同目录独占硬链接，文件系统须支持该能力（本机 NTFS 已测）；不支持时失败，不降级为覆盖写入。使用认证加密遵循 [cryptography AESGCM 文档](https://cryptography.io/en/50.0.0/hazmat/primitives/aead/)；WAL 内存快照格式按 [SQLite 反序列化说明](https://www.sqlite.org/c3ref/deserialize.html)处理。

旧明文格式仅作为显式兼容入口保留：`backup --allow-plaintext` 生成 `.sqlite3` 和 `.manifest.json`；`verify` 校验其 SHA-256/记录数，但不是认证加密；`restore <backup>.sqlite3 --database <db> --yes --allow-plaintext` 同时允许明文恢复和明文安全备份。仅用于已授权迁移/测试，不自动迁移或删除旧备份，也不能用于 `.tpbackup`。正常运维采用加密入口，密钥缺失不会自动改为明文。

源应用数据库本身仍为现有 SQLite，不因此变成列级加密。恢复时为原子替换所需的明文暂存仅写入目标数据库目录，正常失败/成功均清理；该目录、操作账号及备份目录须有受控 OS ACL。进程异常退出可能遗留暂存或操作锁，须人工核查，不自动抢锁或盲删日志。内存备份不证明 OS 页面文件、崩溃转储和宿主机快照不含明文；生产密钥保管/异地副本/介质销毁与操作系统防护另验。

## 2. 恢复演练

先停止所有使用该数据库的应用/脚本，保留反向代理的维护页。恢复命令会在既有目标数据库旁自动创建加密 `pre-restore` 安全备份；因此恢复结果不正确时仍可回到恢复前状态。全新目标没有旧数据，`safety_backup` 为 null。安全备份保留期同样须显式选择。

```bash
docker compose stop taxpearls

# 建议先在独立临时卷/目录验证，再操作正式卷
docker compose run --rm --no-deps taxpearls \
  python scripts/ops_db.py restore-encrypted /data/backups/<backup>.tpbackup \
  --database /data/taxpearls.db --safety-retention-days 30 --yes

docker compose up -d --no-build
docker compose ps
curl --fail http://127.0.0.1:8000/healthz
```

恢复前先认证源备份，再取得同目标运维锁。存在 `-wal` / `-shm` / `-journal` 文件、旧锁或恢复期间目标变化时拒绝覆盖；这些检查不能证明所有外部连接已停止，维护窗口仍是必要前置条件。不要为绕过检查而直接删除 SQLite 日志。发布失败保留已经生成的加密安全备份。

恢复后必须抽查用户数、客户数、审计数、最新审计 ID，并用有权限账号登录查看历史审计；核对原会话、HTML/PDF 归档字节与跨机构拒绝访问。不能只以容器 `healthy` 代替数据验收。恢复输出分别记录源密文指纹与恢复后数据库指纹，二者不是同一种文件。

如需撤销刚才的恢复，停止服务后将输出中的 `safety_backup` 作为下一次恢复源：

```bash
docker compose stop taxpearls
docker compose run --rm --no-deps taxpearls \
  python scripts/ops_db.py restore-encrypted /data/taxpearls.db.pre-restore-<timestamp>.tpbackup \
  --database /data/taxpearls.db --safety-retention-days 30 --yes
docker compose up -d --no-build
```

### 2.1 保留期审阅与单副本销毁

到期不自动删除。先确认专用目录、保留政策、审计/诉讼保留及其他副本，再预览：

```powershell
.\.venv\Scripts\python.exe scripts\ops_db.py retention-plan backups
# 仅预览一个已审阅文件；不带 --yes 不删除，也不生成回执。
.\.venv\Scripts\python.exe scripts\ops_db.py destroy-encrypted backups\manual.tpbackup --directory backups --sha256 <审阅输出的密文SHA256> --reason <审批工单编号>
# 确认该副本可销毁后再执行，回执必须为同目录内尚不存在的 .json。
.\.venv\Scripts\python.exe scripts\ops_db.py destroy-encrypted backups\manual.tpbackup --directory backups --sha256 <同一审阅指纹> --reason <审批工单编号> --receipt backups\disposal-001.json --yes
.\.venv\Scripts\python.exe scripts\ops_db.py verify-receipt backups\disposal-001.json
```

时间以受控主机 UTC 时钟为准，不能只看文件名/mtime。仅审阅直接子文件 `.tpbackup`；目录、符号链接、硬链接、无效认证文件、未到期文件及带同名 `.tpbackup.hold` 标记的文件不可销毁。不递归、不处理其他用户文件，不接收 CLI 人工改时参数。每次仅删除审阅指纹一致的一个文件；实际执行前独占移入自己的临时目录，再重新认证/核对指纹和保留标记。中途变化取消并恢复原文件，原路径被并发占用则保留双方文件供人工恢复，不覆盖并发写入。

回执使用独立派生用途的 HMAC 认证，含操作者、审批说明、时间、密文指纹及恢复路径，不含业务行或密钥，不是第三方数字签名。状态必须单独检查：`prepared` 仅说明执行前留痕，崩溃或回执写入失败时须核对原/临时路径；`cancelled` 表示取消且恢复；`needs_recovery` 表示文件仍留在回执的 `claimed_path`，须人工处理；只有 `completed` 表示该次逻辑删除成功。认证通过不代表状态完成，也不证明其他副本已删除。不得盲目重试或清空 `.destroy-*` 目录。

本流程只证明指定副本的逻辑删除，不保证 SSD、云存储版本、宿主机快照、异地副本或密钥的物理擦除。后者须逐一制定并在真实环境验收；回执和剩余密钥依其独立保留政策受控保存。

## 3. 应用版本回滚

`compose.yaml` 的镜像名为 `taxpearls:${TAXPEARLS_IMAGE_TAG:-current}`。每次上线必须保留不可变版本标签，不能只保留 `latest/current`。

```bash
# 构建并记录发布版本
export RELEASE_TAG=20260923-01
docker build -t taxpearls:${RELEASE_TAG} .
docker image tag taxpearls:${RELEASE_TAG} taxpearls:current
docker compose up -d --no-build --force-recreate
curl --fail http://127.0.0.1:8000/healthz

# 回滚到已验证的旧镜像；数据结构不兼容时须先恢复对应数据库备份
export PREVIOUS_TAG=20260922-01
docker image tag taxpearls:${PREVIOUS_TAG} taxpearls:current
docker compose up -d --no-build --force-recreate
curl --fail http://127.0.0.1:8000/healthz
```

回滚验收必须同时确认：容器镜像 ID 已切回、健康检查通过、登录成功、历史审计可打开、HTML/PDF 报告可生成。失败时保留容器日志、镜像 ID、备份清单和演练时间。
